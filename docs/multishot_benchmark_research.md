# 人脸插件对比与一句话多镜头生成：数据调研

调研日期：2026-10-11（北京时间）。本文为实验设计建议，没有启动生成、下载大规模数据或修改已有分数。

本文保留前期数据调研与备选设计。用户之后确定的当前执行范围以
[20 episode完整视频评测方案](entitybench_collage_vs_3d_evaluation_plan.md)为准：
首轮单组、按原剧本硬切/接续、普通I2V-A14B，独立镜头消融与拼贴对比后置。
下文ST-Bench小样本和独立镜头优先等建议不构成当前任务安排。

## 插件如何公平对比

EntityBench 是数据与输出评测框架；EntityMem 是使用角色参考、拼贴关键帧和记忆条件的生成方法。
EntityMem 的拼贴关键帧用于 memory bank，不意味着所有参评方法都需要拼贴，或每个最终视频首帧
都是未经生成的拼贴。依据：[EntityBench 论文 §4、§5.1](https://arxiv.org/html/2605.15199v1)。

本项目插件作用于图像扩散去噪中间状态。最直接的受控实验是：相同基础首帧模型、prompt、
身份参考、seed、分辨率及 Wan 参数，关闭/开启 v7 3D residual。当前 20 episode 实验支持这个问题。
如果想研究拼贴条件，应在两侧都使用相同拼贴条件，且明确找到可接入插件的图像去噪阶段；
只把拼贴脸替换为 3D 渲染脸会成为另一种算法。直接往视频去噪或 memory bank 注入也需要新适配，
不能宣称现有首帧插件已经支持这些接口。

与 EntityMem 等完整系统对比，可以使用相同 benchmark 输入和输出评分，但只能归因于整体管线；
模型、记忆、资产、采样预算同时不同，不能把总差异全部解释为人脸插件增益。

前置角度采样属于角色资产标定：从同一身份参考构建 Gaussian，再用预设角度渲染并拟合姿态映射。
镜头目标角度来自自身中间结果 pred_x0。报告需列每角色建模/标定成本、每镜头增量成本、失败率，
固定标定/筛选规则，保留失败和负例。额外真实多视角照片或原视频真实姿态要声明额外输入条件。

## 数据候选及实际可用性

| 数据 | 原始输入/规模 | 适合本项目的用途 | 本轮核对状态与边界 |

| [ST-Bench / StoryMem](https://github.com/Kevin-thu/StoryMem#st-bench) | 30 个剧本，8–12 shot/故事，共 300 个 prompt；overview 和 cut 标记 | 低接入成本的完整多镜头管线验证 | 剧本在官方 story/，已打开 [black.json](https://raw.githubusercontent.com/Kevin-thu/StoryMem/main/story/black.json)。原协议提供分镜；改为只给 overview 必须标为改造协议，角色描述/调度需要补充提取与验证 |

Short-Drama-Bench 来源是 [One Sentence, One Drama](https://arxiv.org/html/2605.22144v1)，
该工作也生成多视角角色参考并用 3D 场景约束首帧；其 3D 空间连续性与本项目的局部人脸身份残差
作用不同，可作为相关工作。总体管线相近本身不能证明我们有新贡献。

## 现有端到端基础

[产品 Qwen 管线记录](product_qwen_pipeline.md)已经记载一次中文故事指令经过本地 LLM 规划、
新生成身份/场景资产、FaceLift、273 个角度标定样本、三个 Qwen 首帧、Wan 和 ffmpeg 成片。
输入明确要求一个角色、一个场景、三个镜头；成功输出约 6.125 秒。它证明流程连通，
不证明自主镜头数量规划、身份改进或叙事质量。第三个镜头重复生成背景车辆的问题仍保留。

## 建议的下一轮协议

先保留现有 20 episode 数值评测，另开完整管线实验；没有必要为匹配 EntityMem 而强制拼贴。

1. **固定剧本试验**：优先从 ST-Bench 选取少量适合真人身份的故事，预先冻结选择规则。
   先跑 5 个故事作流程与指标试验，不据此声称完整 benchmark 结果。读取全部分镜，
   固定角色/场景参考、种子及资源预算，两侧只关闭/开启插件。跨场景同一角色复用资产。
2. **一句话输入试验**：采用公开的 logline，或由公开 overview 按固定规则压缩成一句话，
   保存来源、压缩规则及哈希。规划器只接收该句话和固定时长/镜头预算；资产描述和调度由
   规划结果产生。不能把隐藏的原分镜又塞给规划器，或要求与原镜头逐项像素/身份匹配。
3. **插件归因**：一句话先规划一次、生成一次共享身份资产，再分叉成无插件/有插件。
   这同时验证完整流程和插件增量，但不能据此声称规划器优于另一规划方法。
   规划器对比应另做实验，以相同一句话输入、时长、预算评价各自规划与成片。
4. **接续策略**：首轮固定使用现有独立镜头策略。下一轮单独比较尾帧接续，保持两侧策略一致。
   长程 rollout 各侧使用自己的历史状态；双方共享上一 Control 尾帧只能算受控局部试验。
   人脸插件不负责建立整个场景的 3D 空间连续性。
5. **输出与评价**：保留分镜 JSON、角色表、资产/标定来源、每镜头 prompt/seed、首帧、视频、
   有序成片、失败/回退原因和耗时。继续测参考锚定身份及人脸质心，并加入事件覆盖/顺序、
   角色出入与场景/道具状态、视觉质量和成片盲评。LLM/VLM 分数未执行时写缺失。
   原 benchmark 直接使用与输入改造的结果分表；采用官方指标需遵循对应 evaluator。

目前 Wan 默认约 2.04 秒/shot，首轮宜使用可在该时长表达的简单可见动作，明确实际总时长。
复杂对白、剧情反转或分钟级短剧需要另设时长/音频预算，不能仅靠拼接现有短片段宣称已验证。
外部数据接入前核实许可证、字段与缺失文件；本轮只核实公开信息，没有执行付费 API 或生成。
