# 当前Qwen140实验：指标解释与交接结论

更新：2026-10-25（补充人物区域DINO诊断0.7863及接续视觉条件差异；原2026-10-21指标讨论保留）。只讨论 **Qwen＋3D注入＋Wan A14B四步，140集／2491镜头**；当前设置、完整结果和论文对照见[主交接](../LLM_HANDOFF.md)。本页记录已核验事实、抽查观察和解释边界，不新增实验组，不修改官方分数。旧实验只保留[历史引用](history/README.md)，不属于本次交接范围。

## 官方评测执行与指标含义

本次保持作者开源revision `3776439e7037b2128ac3b5d2d1ce63e424cca166`及冻结skip_vlm适配器的非VLM算法，strict、无config覆盖。检测阈值、CLIP匹配、代表裁剪选择、DINO特征和聚合均未为提高分数而调整。媒体和官方评分的[独立核验](../outputs/entitybench_qwen21_i2v_a14b_4step_continuation_full140/audit/final_official.json)已通过，目前未发现执行或数值计算错误。

**按官方代码正确执行，与指标完全等同人工判断，是两件事。** 出现率衡量的是指定实体经过检测和图文匹配后是否判为present，不直接等于人工确认的可见率，更不是身份正确率。抽查中发现人工可见但未通过的样本，不能据此否定官方分数，或把所有低分解释为评测误判。其他方法同样受指标能力限制，不能单独修改我们的阈值、调度或分母来提高排名。

官方非VLM最终结果保持：角色出现率 **0.9212**、物体出现率 **0.8942**、场景出现率 **0.6303**。未运行VLM不是这三个出现率偏低的直接原因；它们由GroundingDINO和CLIP阶段决定。

## 出现率的全量拆分与抽查

读取全部2491个镜头的原始 `_eval.json`，对照冻结manifest的cut、entity_schedule和镜头顺序。证据见[诊断JSON](../outputs/entitybench_qwen21_i2v_a14b_4step_continuation_full140/audit/presence_diagnosis_20261021/diagnosis.json)及[完整采样帧／官方裁剪对照](../outputs/entitybench_qwen21_i2v_a14b_4step_continuation_full140/audit/presence_diagnosis_20261021/inspection.jpg)。没有重新调用检测模型或API。

### 角色：接续镜头通过率较低

| 分组 | present／调度角色-镜头实例 | 实例通过率 |
|---|---:|---:|
| 全部角色 | 4616／4991 | 92.49% |
| 硬切镜头 | 2165／2233 | 96.95% |
| 接续镜头 | 2451／2758 | 88.87% |
| 接续中上一镜头已有调度的角色 | 1035／1120 | 92.41% |
| 接续中上一镜头未调度的角色 | 1416／1638 | 86.45% |

这里的“已有／新进入”只根据相邻两镜头的角色调度名单区分，不是episode中首次出现，也没有证明角色在上一实际尾帧中可见。分组比率是实例统计，**不是最终表的集等权平均0.9212**，不能相互替换。

全部375条未通过的角色记录均为weak，而非无候选框的absent；其中218条CLIP分数在 `[0.18, 0.20)`。weak只表示候选与描述匹配不足，既可能是裁错人／裁错物，也可能是角色缺失、衣服外观不符或画面不清楚，不能直接当作检测误判数量。

375次未通过中，307次发生在接续（81.9%），其中222次属于上一镜头未调度的角色、85次属于已调度角色。该比例描述未通过项的分布，不表示307次全部是新角色入画失败。

**解释假设**：尾帧接续对已有构图有较强约束，下一镜头新增角色或改变构图时，靠文字引导完成变化可能更困难。但论文EntityMem也使用尾帧接续，不能单靠这个共同设置解释方法间出现率差距。更具体的已核实差异是，本次Wan接续阶段没有独立的人物参考和布局视觉条件，而论文提供这些记忆条件；这可能影响新角色进入，仍须对照验证。硬切与接续的内容难度、调度人数等也可能不同，不能据此认定3D注入或四步蒸馏是主要原因。

### 接续输入差异：尾帧相同思路，视觉记忆条件不同

论文EntityMem第4节Stage 3、附录C.1说明，视频模型同时接收本镜头的带名称人物参考图、布局／关键帧组合和文字；接续另将上一镜头末帧作为独立首帧输入，末帧不放进实体记忆库，以免覆盖经过筛选的参考。附录C.2进一步说明，布局模块会处理保留／进入／离开角色，必要时安排多个关键帧。因此接续中新进入角色的参考图可以直接成为视频生成条件。[论文附录C.1–C.2](https://arxiv.org/html/2605.15199v1#A3.SS1)

本次实际[Wan生成脚本](../pretest/run_lightx2v_a14b_4step_qwen140.py)向`pipeline.generate`传入`seed`、`prompt`、单张`image_path`及输出路径。接续时该图是自身前段实际解码尾帧，没有额外人物参考图、布局图或多关键帧输入。Qwen使用角色参考、单人3D注入的步骤属于硬切首帧生成；已有角色素材不会在Wan接续阶段自动再次传入。

例如前段末帧只有A，后段要求B进入：本次输入是A所在的画面＋B入画的文字，EntityMem还可输入B的参考和动作阶段布局。当前可以确认条件路径不同，尚不能确认补充参考就能把本次出现率提高到论文水平；没有相应消融或相同视频骨干的控制实验。该发现不修改正式0.9212，也不说明边界0.9822是整体接续质量优势。

### 场景：候选区域及CLIP匹配影响分数

2441个调度场景实例中，present为1520、weak为921、absent为0；其中373条weak的CLIP在 `[0.18, 0.20)`。实例通过率为62.27%，最终集等权平均为 **0.6303**。这些是本次本地冻结输入的计数，不以论文统计替代。

官方代码从五个采样帧提取候选区域，根据CLIP、清晰度和面积选择代表裁剪，再判断CLIP是否达到0.20。场景可能被定位为局部物体，特写和前景人物也会影响完整场景描述的匹配。

本轮只查看了5组完整采样帧与canonical crop，不是对全部视频或全部weak实例的人工验收。

## 接续边界：高分合理，但与论文的差距仍未解释清楚

### cut和尾帧接续继承了论文设计

EntityBench为镜头提供cut标记。论文第4节Stage 3及附录C.1明确写明：**EntityMem的接续镜头也将上一镜头末帧作为下一镜头首帧输入，并将该帧与实体记忆库分开处理。** 因此，尾帧接续不是我们独有的额外设置，不能把它当成解释我们胜过EntityMem的独立优势。[论文原文](https://arxiv.org/html/2605.15199v1)

| 类型 | 本次处理 | 是否进入边界评分 |
|---|---|---|
| 1136个硬切（`cut=True`，含各集开头） | 按当前镜头要求生成新的Qwen首帧 | 否 |
| 1355个接续（`cut=False`） | 用本路线自身前一视频的实际解码尾帧作为下一段I2V输入，不再次编辑／注入 | 是 |

“硬切重新生成首帧”是本次关键帧→视频路线的实现；benchmark提供边界标记，不代表论文中所有不同架构都必须采用相同的首帧生成管线。论文EntityMem还保留实体参考和关键帧布局，本次不等同于完整复现EntityMem的记忆条件。

### 指标只比较相邻视频的末帧与首帧

冻结开源实现的headline实际使用 `n_boundary=1`，计算前视频末帧与后视频首帧的全画面DINOv2 CLS余弦；不能因为配置存在 `n_boundary_frames=3` 就描述成三帧平均。仅评有效接续，不把硬切计入。定义见论文附录B.4.2；本次1355个实际尾帧依赖已[独立解码核验](../outputs/entitybench_qwen21_i2v_a14b_4step_continuation_full140/audit/final_media.json)，有效边界覆盖137／140集，其余3集保持null。

仅评`cut=False`接续并非本次自行排除难例：论文附录B.4.2公式29明确限定continuation pair；本地冻结代码也仅按该标记收集边界对。末帧作为生成输入与输出首帧逐像素复制是两回事，不同骨干及生成条件对首帧的保留程度可能不同，当前尚未量化其对论文差距的贡献。[论文边界定义](https://arxiv.org/html/2605.15199v1#A2.SS4)

我们的 **0.9822** 表示边界两端的视觉特征接近。尾帧I2V输入保留可以解释这一绝对高分的合理性，但不能评价后续几秒的身份／动作漂移、硬切一致性或全故事质量，也不是“98.22%的接续完全正确”。

### 为什么高于EntityMem的0.7380：当前不能确定

**因为论文EntityMem也使用尾帧接续，仅凭“我们用了上一镜头末帧”不足以解释0.9822与0.7380的差距。** 同样，不能把这项高分归因于3D插件，也不能仅凭高分认定本次偏离了benchmark的接续要求。

已知的可比性限制：论文附录F.2描述匹配内容筛选与coverage修正，固定公开代码的boundary段没有对应的匹配内容／VLM门控；论文描述的跨集实例加权、缺失贡献处理与公开代码的有效集等权平均也存在差异。论文Table15中EntityMem的boundary coverage为1.00，因此不能仅凭“论文做了coverage修正”解释它与我们的全部差距。[论文附录B.4与F.2](https://arxiv.org/html/2605.15199v1)

尚未获得作者对应原始边界帧、视频和表格对应的完整执行配置，无法逐对核查首帧保留程度或量化每项差异的贡献。生成模型、参考条件及实现可能影响分数，但目前只是待验证因素。当前没有证据证明我们在相同口径下比论文具有同等幅度的真实接续质量优势。

## 人物区域DINO、脸部DINO与VLM的边界

- 官方 `cs_face=0.7155` 使用GroundingDINO人物区域的DINO质心相似度，不是人脸身份准确率。衣服、构图、背景、画风及错误定位均可能影响数值。
- 独立脸部裁剪DINO **0.8237** 使用另一套裁剪和有效集合，不是InsightFace或对身份参考的相似度，不能替代官方cs_face或直接对论文排序。
- 39项VLM保持null、调用0；缺少fidelity gate，`cs_face/cs_object`仍标为暂定非VLM结果。以后如果另行授权补VLM，需重新应用门控并重算受影响的跨镜头指标，不能只向原表补空值。
- 当前先不处理VLM，不接入API、不充值、不运行付费评分；官方原分数和冻结配置保持。没有本次新的Control／Treatment视频对照，不能据单路线指标声称3D插件具有因果收益。

## 补充诊断：可见单脸门控与定位纠错后的人物区域DINO 0.7863

本次另行记录 **0.7863**，准确名称为“可见单脸门控＋三项定位纠错后的人物区域DINO”。它来自同一批140集生成视频，是事后子集诊断；正式原始cs_face仍为 **0.7155**，独立脸部裁剪DINO仍为 **0.8237**。三者不能互相替换，也不能据此计算3D插件的增益。

### 具体计算什么

基本单位是一个**集内角色—镜头实例**。沿用官方阶段从五个采样帧中选出的那一张canonical人物区域裁剪；同一集、同一角色在多个镜头中的这些区域，组成该角色的跨镜头比较集合。不同集的同名角色不合并。

**人脸检测只判断原人物区域是否满足筛选条件，不把DINO输入替换成人脸框。** 实际参与DINO的像素仍是原官方人物区域，所以头发、衣服、躯干以及框内背景仍可能影响分数。角色提示词参与上游检测／CLIP选框，最后的DINO质心计算不再用文本匹配。

它比较的是生成结果的跨镜头外观聚集程度，不是生成脸与固定人物参考图的相似度，不是全部视频帧的人脸平均，更不是Control／Treatment注入前后增量。

### 筛选与人工纠错

1. 从原官方标为present的人物区域出发，保留原采样时刻区域内恰有一张合格人脸的裁剪。复用冻结RetinaFace缓存，置信度≥0.90，原分辨率人脸宽、高均≥24像素，人脸框至少80%的面积位于原人物区域内。
2. 同一镜头中，若多个角色声称匹配同一人脸轨迹，则相关项均排除；缺脸、多脸和归属冲突不填0。自动门控后保留1700个区域，其中1383个实例可跨镜头评分，131个有效集的诊断分数为0.7860。
3. 人工复看最低60项与其余实例中固定随机抽取20项，共80项，混排图不显示分数；10项另检查完整采样帧。确认排除3项错角色定位：run227／i25_j77的Walter 3:6、Walter 3:1，以及run4／i35_j83的Ji-hoon 2:1。逐项决策先固定，再重算。没有因为分数低，或发生画风、服装、姿态、身份变化而直接剔除。

该人工抽样偏向低分，不能估计全量错框率；其余区域没有获得完整身份认证。自动规则、逐项判定及输入哈希见[门控计划](../outputs/entitybench_qwen21_i2v_a14b_4step_continuation_full140/evaluation/character_region_visible_face_gate_20261025/plan.json)与[人工纠错记录](../outputs/entitybench_qwen21_i2v_a14b_4step_continuation_full140/evaluation/character_region_visible_face_gate_20261025/remaining_low_score_review/review_decisions.json)。

### 质心计算、聚合和覆盖

筛选后，同一集内某角色至少有两个有效镜头才参与跨镜头评分。把它的单位DINO特征求平均并重新归一化，得到该角色的质心，再算每个裁剪与质心的余弦相似度；质心包含该裁剪自身。集内汇总所有合格角色的裁剪相似度并按出现实例平均，最后对有分数的集等权平均。不是所有角色等权，也不是把全数据集的所有裁剪直接平均。

| 覆盖／结果 | 0.7863诊断版 |
|---|---:|
| 原生成范围 | 140集／2491镜头 |
| 计划角色—镜头实例 | 4991 |
| 筛选及三项纠错后保留的原人物区域 | **1697（34.00%）** |
| 满足跨镜头评分条件的角色—镜头实例 | **1380** |
| 有分数的集 | **131／140** |
| 缺少合格跨镜头集合的集 | 9，保留缺失，不填0 |
| 有效集等权均值 | **0.7863** |

1697是保留区域数，1380是实际计分实例数；均不等于独立镜头数或人物数，一个多人镜头可贡献多个角色实例。其余317项不满足该诊断的跨镜头评分条件，不纳入相似度均值。

重算复用原始DINO两两点积所确定的Gram矩阵、冻结官方质心与聚合函数，没有新增模型或API调用。三项纠错前的结果已数值重现，独立Gram行和公式也已核验。可追溯入口：[诊断结果与覆盖](../outputs/entitybench_qwen21_i2v_a14b_4step_continuation_full140/evaluation/character_region_visible_face_gate_20261025/remaining_low_score_review/recomputed/report.json)、[纠错说明](../outputs/entitybench_qwen21_i2v_a14b_4step_continuation_full140/evaluation/character_region_visible_face_gate_20261025/remaining_low_score_review/README.md)。

对应复现代码随仓库保留：[自动门控及原分数核验](../pretest/evaluate_entitybench_qwen140_region_face_gate.py)、[冻结三项人工定位纠错后的重算](../pretest/recompute_entitybench_qwen140_localization_review.py)。后者与已执行的本地`recompute_review.py`内容一致，读取既有门控、人工决策及原始报告，不重新挑选排除项；运行依赖本机outputs中的冻结输入，交接时不自动重跑。

### 应如何解释与已知问题

**0.7863表示被保留人物区域的跨镜头聚集程度，不表示78.63%的身份正确率。** 相比0.7155，样本覆盖和角色质心均改变，困难样本减少也会影响数值；不能把涨幅称为模型质量提升，也不能和论文方法直接排名。VLM及保真度门控仍未运行。
