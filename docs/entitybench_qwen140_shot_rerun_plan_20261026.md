## 2. 路由与执行Agent：对接续shot选择并执行生成方式

最小版路由决策与拟接入工具链见[接续镜头Agent提示词 v1](entitybench_qwen140_route_agent_prompt_v1_20261026.md)。已用配置中的DashScope多模态API实现独立路由调用，用确定性脚本完成五条镜头的素材／关键帧／视频试跑，并跑通B的首尾帧过渡。当前尚未把这些步骤封装成Agent可自主调用、闭环复核的工具链。

### 2.1 输入与职责

主入口为原标记`cut=false`的shot。Agent读取：

1. 上一shot描述，以及本候选路线实际生成、解码得到的尾帧。
2. 当前shot原始描述、动作、角色调度和地点描述。
3. episode内角色表、已准备的角色素材与统一画风约定。
4. 当前shot的时长预算，以及上一尾帧的画质／可见性问题。

判断核心是：**上一实际尾帧是否已满足当前shot的起始状态；若不满足，剧情是否需要展示中间变化。**

名字、调度名单、原`cut`只是上下文，不能代替实际图像判断。角色名单改变可能是入场、返场、机位转向、画外对白或只露手；名单不变也可能换服装、换景别、换机位。

角色描述检索、拼接、文件哈希和依赖检查由确定性工具负责；目标架构中Agent决定路线、调用关键帧/视频工具并检查实际产物，不重新编造已有角色描述。试跑使用现有`.env.portrait`配置的DashScope视觉模型判断路由；关键帧和视频仍由独立脚本执行并人工复核，未实现Agent自主工具调用。生成Agent与官方VLM评测是不同模块，后者继续关闭。

### 2.2 三个分支

| 路由 | 选择条件 | 生成流程 | 场景视觉信息来源 |
|---|---|---|---|
| A `direct_continue`：直接接续 | 上一尾帧中的人物、空间关系、机位和状态基本合适；只需动作继续发展 | 上一实际尾帧＋强化后的当前动作prompt → 当前视频 | 上一尾帧直接作为Wan起始条件 |
| B `transition_then_continue`：过渡＋主体，两段固定 | 剧情需要观众看到人物进入等连续变化，之后还有可独立执行的镜头行动，且两段可在预算内完成 | 规划目标关键帧 → 首尾帧条件生成入场/过渡 → 从过渡实际尾帧生成主体行动段 | 过渡起点为上一实际尾帧；目标帧也以该尾帧为唯一场景视觉参考 |
| C `new_shot`：重建新镜头 | 主体、机位、拍摄区域或构图明显切换；没有必要展示移动过程 | Qwen结合目标角色素材、当前描述和画风生成新的动作起始帧 → Wan生成视频 | 同一环境且上一尾帧有相容信息时作参考；若换地点或旧人会污染目标图，记录理由并舍弃该参考 |

对B固定采用“入场/过渡＋主体行动”两段。生成前从原始shot拆出`transition_action`与非空的`main_action`；原文若只有入场、没有后续行动，首版返回`needs_review`，不为凑第二段编造动作。生成后检查实际视频是否符合分工；若过渡段意外提前完成主体行动或没有完成过渡，记录失败并有界重试／复核，不静默跳过第二段。A也需检查尾帧质量；人物／构图相容，不代表模糊或身份已漂移的输入适合原样继续。

### 2.3 典型例子

| 原始镜头关系 | 建议路由 | 理由 |
|---|---|---|
| run700，i25_j50，3:1→3:2：Stefan翻找藤篮，然后停下抬头 | A | 人物、桌子、藤篮和机位已就绪 |
| run771，i25_j42，1:4→1:5：Victor继续拿墙上电话讲话 | A | 人物、服装、听筒、姿态和背景可直接延续 |
| run484，i15_j47，5:2：Chloe和黄色夹克男孩Leo进入客厅、走近花纹沙发 | B候选 | 过渡展示进入、主体段展示走近沙发；原视频已有进门动作却入错人物，目标关键帧必须落实Leo身份和衣服 |
| run298，i40_j64，23:1舞台演唱→23:2调音台男子交谈 | C候选 | 同一场馆内切换拍摄区域和主体，不应强制把两名男子走入原舞台构图 |
| 同一集23:2→23:3观众席视角广角看舞台 | C候选 | 需要重新建立机位与构图，不必强制生成摄影机移动 |

以上是已讨论样例和初始建议，实际执行仍看本候选路线的尾帧。原视频已有错误时，不能假定其尾帧符合原文字。

### 2.4 B分支执行细节

1. 在生成前规划起始状态、目标状态、过渡动作和非空的`main_action`。目标状态要绑定正确角色素材，约束旧人物、场景元素、画风和空间关系。
2. 首尾帧过渡以“自身上段实际尾帧”为起点，目标关键帧以它为唯一环境视觉参考生成。角色素材是额外的人物参考，不是额外环境素材。
3. 预检首尾帧后端的长度、分辨率、角色保持和端点行为；记录模型、权重、采样、精度、耗时等。不能直接将当前A14B四步I2V视为已支持首尾帧，也不能宣称更换过渡后端只改变了路由。
4. 检查过渡**实际生成尾帧**是否满足人物、衣服、布局、画风和动作阶段要求。不能用预先指定的目标图片冒充实际尾帧接后续视频。
5. 必须从过渡视频的实际尾帧生成第二段，只执行`main_action`，避免把“人物入场”等已完成动作再次执行。若实际过渡视频与规划不符，记录失败并有界重试／复核。
6. 拼接“过渡＋主体行动”两段。总帧数／帧率应与原shot预算一致，处理接缝重复帧；分段帧数受模型支持约束，具体分配在预检中确定。若无法在原预算内实现，明确记录为改时长实验，不能当作同预算对照。

### 2.5 C分支：上一尾帧是可选的环境参考

Qwen输入分工应明确：在上一尾帧与目标地点相容时，它提供当前可观察的场景风格、灯光、材质及空间线索；其余图片绑定目标角色。根据当前shot重排主体、景别和机位，不强制保留上一图中的旧人物或构图。上一尾帧含无关地点、错误人物或复制风险时，允许不输入该图，记录`environment_reference_skipped_reason`；run1404的首版关键帧因引入不相关街景尾帧复制了Kenji，第二版舍弃该图并修正。

上一尾帧和人物素材需要共同计入生成工具的多图输入上限。若超限，采用明确记录的分批编辑方案或报告暂不支持，不能静默省略部分角色参考。

上一帧没拍到的区域只能由当前文字补全。例如歌手面部特写不能唯一决定调音台布局。Agent记录环境参考是否充分，不把补出的不可见区域称为已验证的空间一致性。本轮不额外生成全景背景或环境多视图素材。

生成新首帧仍以当前动作的**起始状态**为目标。若本shot随后需要人物走入或取物，不应把人物直接画到终点，或把取物动作提前完成。

### 2.6 原硬切shot的处理

原`cut=true`仍先建立新镜头的动作起始帧，不从上一scene尾帧强制生成跨场景连续运动。若镜头内部确实有需展示的入场或复杂动作，可以在新镜头起始状态与目标状态之间采用B式分段；两端都是当前新镜头内部状态。

如果需要环境视觉参考，仍只允许上一shot实际尾帧；目标地点变化时，可直接按当前文字建立新环境，不强行保留旧地点几何。每个episode第一个shot没有上一尾帧，记录环境参考为null，按原地点文字和episode画风建立首帧，不借用其他episode图片。

### 2.7 结构化输出与失败处理

执行器最终manifest至少保存以下字段；这**不是Agent的路由决策输出**，路由决策只返回路线、理由以及B/C所需状态与动作。以下是待实现的数据约定，不是当前已存在的运行接口：

```json
{
  "episode_id": "完整episode_id",
  "shot_key": "23:2",
  "original_cut": false,
  "generation_route": "new_shot",
  "reason": "主体与拍摄区域切换，剧情不要求连续运镜",
  "parent_video_sha256": "...",
  "parent_tail_sha256": "...",
  "target_characters": ["Julian", "Simon"],
  "environment_reference": "own_previous_actual_tail",
  "environment_reference_sufficient": false,
  "target_start_state": "调音台后两名男子半身构图，开始交谈",
  "segments": [{"kind": "main", "action": "当前尚未执行的动作"}],
  "style_spec_sha256": "...",
  "character_asset_sha256": {"Julian": "...", "Simon": "..."}
}
```

另保存Agent原始输入、输出、版本、派生prompt、各段时长与产物SHA。解析失败、素材缺失或目标状态不合格时记录原因并进入有界重试／复核，不静默退回某个分支冒充路由成功。具体重试上限在实现时作为配置冻结。

## 3. 视频生成提示词强化：查表补全，不让Agent重写角色

### 3.1 确定性拼接

对每个需要生成的shot：

1. 以`episode_id＋角色名`查询当前episode的`entity_descriptions`，不能跨集按同名人物复用。
2. 补齐当前shot所需的全部角色描述，包括首次出场、保持在场和返场角色。
3. 结合当前shot明确要求的服装、道具和状态；具体镜头状态优先于全局默认服饰，保留差异记录，不能同时拼入互相冲突的要求。
4. 将角色描述、当前必要环境／道具描述、episode画风和当前阶段动作组合成派生生成prompt。原始benchmark prompt保留原文，供审计和官方评测使用。
5. 原prompt已有相同定义时去重，不重复堆叠。检查文本编码长度；超限时先减少重复和无关内容，保留角色区分与核心动作，不静默截掉关键角色。

示意结构：

```text
统一画风：{episode_style}

角色定义：
Julian：{查表得到、结合本shot状态的描述}
Simon：{查表得到、结合本shot状态的描述}

当前环境与必要道具：{当前shot已有描述}

当前阶段动作：{完整shot动作，或分段后尚未执行的动作}
```

### 3.2 多人对应关系

当前Wan只接收图片和文字，不接收Qwen阶段“图1=A、图2=B”的独立绑定。完整描述可以帮助图文对应，但不保证身份／动作不会交换。

**首版只做已有描述的查询和拼接，不强制新增逐镜头人物定位模块。** 左右、前后、衣服所在区域是实际起始图中的动态信息，不在静态角色表中；确需补充时必须看图确认，只描述起始状态，不能按调度名单顺序编造，不能把位置描述当成全程固定轨迹。

### 3.3 各阶段使用方式

| 生成阶段 | 内容 |
|---|---|
| 人物素材 | 角色原描述＋episode画风＋单角色构图约束 |
| 新首帧／目标关键帧 | 角色参考绑定＋完整角色描述＋episode画风＋所需起始／目标状态；环境参考仅上一实际尾帧 |
| A视频 | 完整角色描述＋episode画风＋当前动作 |
| B过渡 | 对应角色描述＋episode画风＋明确的状态变化／过渡动作 |
| B主体行动段 | 完整角色描述＋episode画风＋`main_action`；使用过渡实际尾帧 |
| C视频 | 完整角色描述＋episode画风＋当前动作；使用新首帧 |

当前蒸馏视频路线CFG关闭，不能把新增负面提示词当作已经生效的质量控制；需要的风格和动作要求先落实到实际生效的正向条件。首版不同时更换步数、分辨率、LoRA和采样配置，以减少额外变量；B所需后端变化单独记录。

## 4. 画风约束与素材检查

### 4.1 episode级画风约定

每个episode建立一份版本化`style_spec`，包含媒介类别（如二维动漫、三维动画或写实）、人物渲染方式、材质与线条特征等。依据原始故事、实体与镜头描述确定，保留选择依据；不能根据某一张偶然生成的写实头像决定整集写实，也不把所有故事统一改成同一种风格。

整集画风约定不等于每个镜头都必须同样明亮。当前shot明确要求的夜景、剪影或特殊灯光仍保留。风格证据含糊时记录不确定性，在小样本中先固定一种与故事相容的选择，不让各角色或各阶段分别猜测。

将同一约定传给人物素材、新首帧、过渡目标帧、过渡视频和主体视频，并在每阶段检查实际产物。仅在prompt加一句风格词不等于输出已满足约束。

### 4.2 人物素材检查和补齐

先为重跑目标及其依赖范围建立素材清单，覆盖所有实际需要的角色，不再只准备原硬切调度角色。run298 i40_j64的Simon未列入旧素材清单，属于需要补齐的实例。

已有素材符合角色和画风就版本化复用；存在混风、多人、拼图、错误角色或描述明显冲突的素材再重建。一个角色参考应清楚呈现一个角色，不把“单人提示词已写”当作检查通过。

这里区分文字角色描述、二维人物参考图和3D人脸资产。全部992个episode-local调度角色都可从原始episode的`entity_descriptions`查到文字描述；当前实验只为曾在硬切shot调度的711个角色计划生成二维人物参考图。其余281个角色只在接续shot调度，本实验没有为他们计划生成二维人物参考图，也没有对应的3D人脸资产。711个角色中，仅226个被标记为`needs_face_asset`、进入3D资产准备候选范围；是否真正得到可用资产还需逐人查产物。即使某角色已有普通参考图，也不代表有可用的FaceLift/3D资产。对首批重跑镜头逐人核对这两类资产，再决定是否尝试注入。

如果人物参考改变，保存新版本和SHA，并追踪所有使用它的首帧／视频。后续若使用FaceLift Gaussian与标定，必须与新参考重新绑定，不能按角色名沿用旧参考对应的3D资产。

### 4.3 3D注入与画风

当前代码没有动漫／写实风格门控，人脸检测通过不等于适合注入。路由Agent也不能据此把动漫角色判成写实。

针对明确动漫画风，首轮建议优先使用Qwen原生角色参考，现有3D注入不默认启用，收益另做配对验证；这是拟采用的实验分流建议，不是已有因果结论。若本轮改变注入开关，必须显式记录，不能把系统结果归因于路由单项改动。多人素材绑定、3D资格与三分支生成路由分别管理。

**重新生成关键帧与3D注入并不互斥，但加入环境参考的注入路径尚需适配。** 当前Qwen注入本身已经以“提示词＋人物参考图片”为条件，3D residual作用于目标图的中间去噪状态，不是只能用于纯文本生成，也不是生成后直接贴一张脸。原则上可将上一尾帧作为额外环境条件，在生成新首帧或过渡目标帧时对可用目标脸应用注入；是否保持构图、背景和身份，需要实际验证，不能视为现有入口已支持。

现有`run_qwen_image21_shared_prefix_adaptive.py`的官方Control分支和Treatment条件重建都只从`record['characters']`提取输入图。适配时应分开管理“全部条件图片及其角色／环境用途”和“待注入人物”，统一两分支的图片顺序、prompt绑定及条件编码。上一尾帧不是一个新角色，不能塞进人物名单让它被构建3D或参与身份映射；环境图内旧人物造成的目标脸歧义也应记录并跳过，不能强制注入。继续保持同条件、同latent分叉，先做兼容性检查，不自动扩展本轮已验证的单人注入范围。

| 图像类型 | 本计划中的注入处理 |
|---|---|
| 上一视频实际尾帧，作为过渡起点或环境参考 | 保留其真实像素与来源，不为接续重新注入这张已生成图 |
| Qwen重建的动作起始帧 | 新图去噪时可选注入，前提是风格、目标脸与3D资产门控通过，且环境条件路径已验证 |
| Qwen生成的过渡目标关键帧（指定尾帧） | 同上；目标脸不可见或无法可靠映射时跳过，不能为了注入提前让角色露脸 |
| 视频模型实际输出尾帧 | 与指定目标关键帧区分；从视频实际解码取得，不事后注入并冒充原视频尾帧 |

首轮先跑通三分支及角色／画风条件，并将“加入环境参考后的3D适配”作为独立验证项。未完成适配的样例明确标注仅使用Qwen原生参考；这表示当前执行状态，不代表新关键帧在原理上不能用3D注入。

### 4.4 三条路由中的注入位置与多人画面

**单人注入的现有实验条件是“该硬切shot只调度一名角色且其参考/3D资产合格”，不是“新角色只有一名”，也不保证生成图中只有一张脸。** 若上一尾帧已有旧人物，新角色入场后的目标画面可能同时有新旧多张脸。当前实现会先按面积截取至多`len(characters_spec)`张脸，再做角色匹配；只传一位新角色时，旧人物的脸若更大，就可能被误当作新角色注入。现有身份相似度主要控制注入步数，并不是阻止这种错误映射的可靠拒绝门槛。这类目标图在没有更严格的定位/身份门控前关闭3D注入。

| 路由 | 是否生成新的Qwen图 | 本轮注入策略 |
|---|---|---|
| A 直接接续 | 不生成；上一实际尾帧直接交给Wan | 不在已有尾帧或Wan视频上做3D注入。若新人物必须在后续动作中出现，靠文字促使其出现风险仍高，应重新判断是否适合B或C。 |
| B 过渡＋后续段 | 生成过渡**目标关键帧**，上一实际尾帧作为过渡起点 | 目标帧输入旧尾帧作为环境/旧人物参考，新人物使用其人物参考图；旧人物如有可用素材也可加入人物参考。先用Qwen原生多图生成。只有新角色的目标脸可见、能可靠定位/确认且3D/画风门控通过时，才另做单目标注入实验；实际过渡尾帧由视频解码取得，不能拿目标图冒充。 |
| C 重建新镜头 | 生成新的动作起始帧 | 上一尾帧只是环境参考，目标人物使用各自素材。生成图若含多人，首轮用Qwen原生多图参考；仅在目标脸明确且适配完成后，另做单目标注入实验。 |

例如旧人物A已在上一尾帧，新人物B走入并和A同框：B路线规划一张过渡目标关键帧作为端点，再用首尾帧后端生成可见的入场过程；**第二段必须从过渡视频的实际尾帧开始执行原shot的主体行动**。端点要同时保留A并加入B，不要求画面只有B一张脸。若B脸不可见、不够清晰，或无法从A脸中可靠区分，就跳过B的3D注入；先保证人物参考、入场过程及过渡实际尾帧正确。本轮已在单例上跑通本地四步`flf2v`后端；动作是否真正呈现入场仍需单独验收。

后续如启用单目标注入，应先从完整候选图检测所有脸，结合目标人物参考、位置/外观证据给出目标脸的绝对相似度与歧义判断，不能先按面积截断后强制把剩余脸赋给新角色；不确定时直接跳过注入并保留原生生成结果。该门控与“Qwen能接收多张条件图”是两个独立能力。

### 4.5 接续镜头的单目标注入筛选（待实现）

路由先按剧情和实际尾帧决定，注入筛选只作用于B的目标关键帧、C的新动作起始帧；不为了获得注入资格改变A/B/C路由。首轮采用保守门控：

1. 查当前关键帧**此刻**应出现且需要增强的目标角色。只指定一名`injection_target`；目标若尚未入画、背对、只露手或脸不可辨，就不为注入提前改变剧情状态。A没有新Qwen图，直接标记`no_qwen_keyframe`。
2. 核对该角色的二维参考图是否为正确单人、是否有与它匹配的可用FaceLift/3D资产，并按episode画风规则判断是否启用3D。原`needs_face_asset`只是旧硬切计划标记，不可直接当作接续镜头的资格判断；只在接续出现的281个角色需要先补二维参考图，3D资产另按本候选需要准备。
3. 先按同一组人物图、环境尾帧、图片编号、prompt和seed生成Qwen原生Control，并检查实际候选图与注入点预览。检测**全部**可见脸。首轮仅放行“可靠检出一张正面/可识别的脸，且有证据确认它是目标角色”的关键帧；人物描述、衣服/位置以及与旧角色的参考/尾帧对照可辅助确认，不能仅靠脸数=1推断身份。零张或多张可见脸、旧人物脸占据唯一位置、目标身份含糊，均回退原生Control。动漫画风默认不走现有3D注入，除非单独配对验证通过。
4. 通过门控后才尝试单目标3D注入，并对比Control/Treatment的目标脸、非目标区域和画风。若出现误脸、风格漂移或角色没有在实际视频中保持，记录失败并回退Control；视频尾帧始终来自解码产物。现有Control/Treatment输入都必须适配额外环境图，且条件顺序完全一致。

记录`generation_route`、`keyframe_kind`、`injection_target`、人物参考与3D资产SHA、全图检出脸数及目标框、身份判定证据、`injection_skip_reason`、Control/Treatment哈希和最终选用版本。未来若要支持“旧人物A和新人物B同框、只注入B”，须改为检测全图后对A/B作可靠对应，再局部注入B；不能沿用现有先按面积截脸的单人入口。

### 5.2 依赖闭包：不能只换一个视频再接旧缓存

同一条候选路线按原次序执行。局部实验的未改动父镜头可以作为冻结基线锚点导入，记录来源和SHA；从第一个被改动节点开始，下游使用本候选实际产物。

1. 当前shot视频变化，会改变尾帧，因而下一个接续shot的路由判断、输入与视频缓存都需要重新验证。
2. **C虽然生成新首帧，但环境参考仍依赖上一实际尾帧，不能自动当作依赖断点。**
3. 沿依赖向后扩展，直到到达不依赖已改动父段的原硬切／独立首帧节点；且该节点的人物素材、画风、prompt和模型配置未改变，才能安全复用。
4. 如果改变episode画风或某个角色素材，要额外纳入所有受其影响的镜头，可能越过原硬切边界。重跑范围由实际依赖决定，不保证始终只重跑最初选中的几个shot。
5. 区分“问题目标shot”和“为保持路线成立必须重跑的依赖shot”。前者用于定向效果比较，后者也要记录结果，不能只保留改善项。

单shot机制对照可以固定同一个未改动父尾帧，分别测试原prompt和补全prompt等；这种固定输入对照与沿新尾帧执行的完整局部替换路线分别标记，不能混算。

### 5.3 执行顺序

1. 冻结问题清单、原视频、原首帧／尾帧、素材与基线评分，明确依赖范围。
2. 实现确定性角色描述补全、版本化画风约定和缺失素材清单。
3. 在样例上实现Agent三分支规划与日志；先检查分支、起始态和目标帧是否符合原剧情。
4. 分别验证A、C和B；B的首尾帧后端、分段时长和实际尾帧衔接单独预检，不因一条分支未就绪而将其他结果伪装成三路完整实验。
5. 对问题shot及依赖范围生成新候选，保留原基线，逐镜头比较。
6. 尽量保留“只补prompt”等小对照以辨别贡献；如果同时改变画风、素材和路由，结论只能是组合方案效果，不能归因单项。
7. 样例质量与依赖校验通过后再扩大局部范围；此后是否扩到全140集属于后续安排。

运行前重新检查当前GPU、cgroup内存、CPU和磁盘，不根据历史48GB GPU配置直接启动。Agent模型、调用方式与过渡模型在实现阶段确定并记录；本方案没有选定或启用付费API。

## 6. 比较、评测与验收

### 6.1 人工验收先看什么

- 指定角色是否出现，外观是否符合角色表与本shot状态；多人有没有交换动作、复制或变形。
- 动作是否发生，以及新人物／新机位何时建立；将首次可见时间和首次可确认身份时间分开记录。
- 画面是否符合当前shot的主体、景别、拍摄区域和动作顺序，是否仍困在旧构图。
- 素材、首帧、过渡、视频是否保持episode画风，是否出现局部写实脸混入动漫等情况。
- 过渡是否自然、终点是否正确、拼接是否停顿或重复动作，后续有没有继续变糊／漂移。
- 记录成功、失败、不确定和回退；不只展示正例，不把入场动作存在等同于入对角色。

### 6.2 官方指标口径

官方非VLM评测沿用冻结算法、阈值和原始评测描述。派生生成prompt用于生成，不覆盖用于评测的原benchmark文本。VLM／保真度门控继续不运行，缺失项为null，`cs_face/cs_object`继续按非VLM暂定结果解释。

已在四个完整episode、43条视频上试行这一口径：run714、run484、run755的角色出现率提高，run1404保持不变；`cs_face`在run755、run1404提高，在run714、run484下降。数值和失败裁剪见[四集复评报告](../outputs/entitybench_qwen140_rerun_pilot_20261026/official_subset_v1/report.md)。`present`只代表区域/文本检测通过，`cs_face`按被选中的同名区域相对跨镜头质心计算；run484旧片的“Leo”裁剪实际上是白外套成年人，自动身份分不能取代人工核对。run714用本集更早的正确Leo外观作身份锚点，`cs_face`较无锚点版回升，但举相机遮脸仍影响裁剪相似度；放慢举相机动作后评测器仍选中遮脸帧，未再改善该分数。因此下轮必须同时存档角色裁剪与选中帧，按实际人物正确性、动作语义和画风判断是否收片。

返场角色新素材不应逐shot独立随机生成。优先使用同一episode已经核对为正确的早期出场锚点；首次出现角色则冻结资产版本并追踪后续依赖。若早期出场本身是错人，先修复该锚点，不要让错误身份向后传播。画风混杂可先在素材和首帧阶段校正，但现有官方指标没有单独的画风一致性真值项，需配合逐帧人工/视觉检查。

局部VBench／presence诊断可以按shot展示；**跨镜头`cs_face`和episode汇总必须基于完整受影响episode重算**，因为新区域会改变角色质心、检测覆盖及边界。不能只比较被重跑shot的旧新质心分，也不能沿用已经受输入变化影响的评分缓存。

保留`original_cut`和原shot编号，内部子段拼接为原shot后再评测。对原标记`cut=false`但实际选择C的边界，仍按原口径评分，不能为提高边界分或改变分母而删除这些边界；另外记录实际编辑／生成路由，解释内容正确性与边界连续性的取舍。

如需得到完整新路线总表：构建每个原shot恰好一个视频的候选清单，所有复用项核验SHA及来源；受影响episode完整重评，其他episode仅在输入／配置完全一致时复用有效缓存，最后通过官方反序列化器／聚合器按原split汇总。不得把定向挑出的低质量子集收益称为全140集提升。

除质量外记录新增素材、关键帧、Agent和视频生成耗时、失败重试与资源开销。只有新增实测结果才能报告收益和成本。
